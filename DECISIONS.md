# Decisions

Dated entries: what was decided, and why. Newest milestone at the bottom.

## Milestone 0 (2026-11-16)

### Where the spec and the M0 brief differ (the brief wins for M0)

| #   | Decision                                                                                                             | Reason                                                                                                                                                                                                                              |
| --- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Content JSON lives in `/content` at the repo root; `src/content` holds only code.                                    | Spec section 9 puts "piece JSON" in `/src/content`; spec section 7 and the brief say `/content`.                                                                                                                                    |
| 2   | The clef and key signature are drawn on every system; the time signature only on the first.                          | The brief says "key and time signatures on the first system". Repeating the clef and key on each line is standard engraving, and it is what the learner will meet in real sheet music. Say if you want it on the first system only. |
| 3   | CI checks run on every push and pull request; the deploy runs only for `main`. The Playwright suite also runs in CI. | The brief's workflow is "on push to main"; the acceptance criteria also ask for the Playwright suite to pass in CI, and checking branches before they reach `main` catches problems earlier.                                        |

### Music core and content format

| #   | Decision                                                                                                                                                         | Reason                                                                                                                       |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 10  | Token grammar order is `pitch/duration[.][t][_][@string-fret][~finger]`: the tie mark comes straight after the duration, and `@` comes before `~`.               | The brief gives the parts but not their order when combined. One fixed order keeps the parser and its error messages simple. |
| 11  | Minor keys are written with an `m` suffix (`Am`, `Em`, `Dm`, `Bm`, `F#m`, `C#m`, `Gm`, `Cm`). Modes such as "A Dorian" (Scarborough Fair) are not supported yet. | The brief lists majors "and relative minors" without a spelling. Modes are needed first in M4.                               |
| 12  | A tie must lead to a note of the same pitch; a tie on the last note, or into a rest, is a validation error.                                                      | Otherwise it is a slur, which the format does not have.                                                                      |
| 13  | A tied-to note never shows its accidental again, and an accidental lasts to the end of its bar for that line or space only (each octave is separate).            | Standard notation practice; the brief leaves it open.                                                                        |
| 14  | Content file `id` must match the file name, and ids must be unique. `suggestedTempo` must be 30 to 220.                                                          | Cheap checks that prevent confusing bugs later.                                                                              |
| 15  | The JSON files are formatted by Prettier, so `"key"`, `"time"` and `"position"` sit on separate lines. Notes and values are exactly as given in the brief.       | One formatter for the whole repo.                                                                                            |

### Fingering function

| #   | Decision                                                                                                                                                                           | Reason                                                                                             |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 16  | When a pitch can only be played as a stretch and both stretches are possible (for example C#4 in 5th position: string 6 fret 9 or string 5 fret 4), the higher string number wins. | The brief only says home beats stretch. Reusing its tie-break rule keeps the function predictable. |
| 17  | The `key` argument is accepted but does not change the result.                                                                                                                     | The brief asks for it in the signature; none of the M0 rules depend on key.                        |
| 18  | A `@string-fret` override may place a note outside the declared position (overrides always win), but the stage check still applies to the pitch.                                   | Lets content mark an intentional shift or open string without weakening the stage rules.           |
| 19  | A `~finger` override must agree with the fret: finger 0 only for an open string, 1 to 4 only for a fretted note.                                                                   | The brief asks for overrides to be "physically valid".                                             |
| 20  | Positions up to 16 are accepted; frets 0 to 19.                                                                                                                                    | The brief sets the fret range; position 16 is the highest whose home frets fit on 19 frets.        |

### Stage check

| #   | Decision                                                                                                                                                                                                                                        | Reason                                                                                                                         |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 21  | In key C, any accidental makes the piece P5. Key Am is always P5, even with no accidentals.                                                                                                                                                     | Follows the brief's wording ("any accidental outside the key, or key D or Am").                                                |
| 22  | Open-position pieces in keys the M0 list does not name (A, E, Bb, Eb, Bm and so on) fail with "stage not supported yet".                                                                                                                        | Those keys belong to P7 and P9; M0 covers P1 to P5.                                                                            |
| 23  | Dotted eighths, dotted whole notes, dotted sixteenths, triplets and meters other than 2/4, 3/4, 4/4 fail with "stage not supported yet". A dotted-quarter rest counts as R4. Sixteenths count as R5 whether or not they come in groups of four. | The brief names what R1 to R5 contain; everything else is later stages.                                                        |
| 24  | The parser accepts triplets (`8t`), but the renderer refuses to draw them.                                                                                                                                                                      | They are part of the format (spec section 7) but need tuplet brackets, which arrive with R8. The validator rejects them first. |

### Notation

| #   | Decision                                                                                                                                                                                                                                                           | Reason                                                                                                                      |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 25  | Each system (line of music) is its own SVG holding a notation stave and a tab stave. Both are always laid out together; Peek tab only shows or hides the tab group and changes the system's height.                                                                | Guarantees that toggling the tab cannot move the notation sideways, and makes "scroll the current system into view" simple. |
| 26  | At most 4 bars per system; bars are stretched to fill the line, but never beyond 420 px each (before zoom).                                                                                                                                                        | Keeps short final lines from being spread across the whole width. Both numbers are in `config.ts`.                          |
| 27  | Finger numbers sit left of the notehead and circled string numbers above it. At `first-of-bar` they go on the first note of the bar (not a rest). A note tied from the previous one gets no markers.                                                               | Classical guitar convention; the brief does not say where they go.                                                          |
| 28  | In tab, a note tied from the previous one is shown in brackets, and rests are left blank.                                                                                                                                                                          | Common tab practice; nothing in M0 content uses ties or rests yet.                                                          |
| 29  | Default staff zoom is 120%, adjustable 80% to 160% in steps of 20% (dev control).                                                                                                                                                                                  | Readable at 1280 px with 4 bars per line.                                                                                   |
| 30  | VexFlow's built-in default colours (stems, staff lines) are set through its global metrics table at each draw.                                                                                                                                                     | VexFlow 5 has no per-renderer setting for these; without it stems stay black in the dark theme.                             |
| 31  | Note handles are exposed as `renderer.handles` (a map keyed by `"bar:note"`) and `renderer.getHandle(bar, note)`. Each handle has the notation element, the tab element, the system index and the note's x position. Rests have a handle too, with no tab element. | The brief asks for the map as public API for M1.                                                                            |

### Timing and playback

| #   | Decision                                                                                                                                                                                                                                                                                   | Reason                                                                                                                                                           |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 32  | One beat is one quarter note everywhere, in every meter.                                                                                                                                                                                                                                   | Tempo is quarter-note BPM (brief, task 7). Compound meters (R8) may want a dotted-quarter beat for the metronome; the timeline will not need to change for that. |
| 33  | `NoteEvent` has three fields beyond the brief's list: `index`, `isRest` and `soundingBeats`. Rests are events with `soundingMidi: null`. A tied group's first note carries the whole sounding length in `soundingBeats`; `durationBeats` is always the written length of that one note.    | The playhead needs every written note, including rests and tied notes, to keep its place; the sampler needs the combined length.                                 |
| 34  | The clock runs the Tone.js Transport at 192 ticks per beat and schedules in ticks.                                                                                                                                                                                                         | Tick scheduling follows tempo changes with no restart, and every duration in the format (including triplets) is a whole number of ticks.                         |
| 35  | `clock.beat` reports the beat being _heard_ now (at the audio context's current time), not the slightly later time Tone is scheduling for.                                                                                                                                                 | Tone schedules about 0.1 s ahead. Reading the scheduling position would put the playhead ahead of the sound.                                                     |
| 36  | The playhead and highlight are placed on each animation frame by reading `clock.beat`. Only the end-of-piece stop uses Tone.js `Draw`.                                                                                                                                                     | Reading the clock every frame cannot drift and needs no bookkeeping when the tempo changes or the score is redrawn.                                              |
| 37  | A note's length in seconds is fixed at the tempo in force when it is struck.                                                                                                                                                                                                               | A tempo change while a note is ringing changes when the next note starts (exactly), not how long the ringing one is held. Plucked notes decay anyway.            |
| 38  | At the end of a piece the last note rings out; pressing Stop cuts the sound at once.                                                                                                                                                                                                       | Sounds natural at the end, responsive on Stop.                                                                                                                   |
| 39  | All 44 semitones from sounding E2 to B5 are bundled (about 780 KB), named by MIDI number.                                                                                                                                                                                                  | No sample is ever pitch-shifted, and the whole set is small. Files are fetched at page load, before the first Play.                                              |
| 40  | The only timer in `src` is the resize debounce in `src/ui/app.ts`. A unit test fails if any other file uses `setTimeout`, `setInterval`, `Date.now()` or `performance.now()`, or if any file but `clock.ts` touches the Transport. ESLint also bans `setInterval` and `Date.now` in `src`. | Enforces the brief's "all timing goes through the clock module".                                                                                                 |

### UI

| #   | Decision                                                                                                                         | Reason                                                                                                      |
| --- | -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 41  | The theme choice is stored in `localStorage` (`malcotron.theme`).                                                                | The IndexedDB settings store arrives in M3 (brief, task 8).                                                 |
| 42  | The colour palette is defined in `src/ui/theme.ts` and applied as CSS custom properties, rather than written in the stylesheet.  | The renderer needs real colour values to draw with, and a unit test checks every pairing against WCAG AA.   |
| 43  | UI font is the system font stack.                                                                                                | No font files to host or license.                                                                           |
| 44  | The dev piece picker also reads `?piece=<id>` from the URL.                                                                      | Lets tests and bug reports open a piece directly.                                                           |
| 45  | The page exposes `window.malcotron` (renderer, player, clock, playhead, theme, and `show(json)` to draw any valid content JSON). | Used by the end-to-end tests and handy in the console. It can be removed or hidden behind a dev flag later. |

## After the first M0 review (2026-11-16)

| #   | Decision                                                                                                                                                                                                      | Reason                                                                                                                                                                                                 |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 46  | Tab fret numbers, finger numbers and string numbers are drawn in the UI font (system sans-serif), not VexFlow's default "Bravura, Academico".                                                                 | The product owner saw strange characters in place of some tab numbers. Bravura is a music font; which glyph a browser picks for a digit when it is listed first varies. The UI font always has digits. |
| 47  | Each system's height is worked out from the notes on it (ledger lines, stems, markers), replacing the fixed heights from decision 25. The spacing allowances are in `config.ts`.                              | With the tab shown, fixed heights wasted room and forced scrolling. It also makes room automatically for high ledger lines in later positions.                                                         |
| 48  | The piece picker and staff size moved into the header, and the title, composer and key share one line.                                                                                                        | Gives the score about 80 px more height.                                                                                                                                                               |
| 49  | When the system being played is not fully visible, the score scrolls it to the top of the view (previously: just far enough to be visible). The same happens when the tab is shown or hidden during playback. | The learner should never have to scroll by hand, and should see as much of what comes next as fits.                                                                                                    |
